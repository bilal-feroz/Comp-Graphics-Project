The Three Sacred Raster Algorithms (`raster.py`)

🎮 Interactive Bresenham & Circle Pixel Playground

1. Bresenham's Line

Draws lines using only integer addition and subtraction (no slow float division!).

dx = abs(x1 - x0)
dy = abs(y1 - y0)
decision d = 2*dy - dx
if d >= 0: y += sy, d -= 2*dx
d += 2*dy

✨ Covers all 8 octants (steep & shallow, any direction)!

2. Midpoint Circle

Uses 8-way symmetry: only calculates 1/8th of the circle, then mirrors it to all 8 octants!

d = 1 - r
while x <= y:
  plot(xc±x, yc±y), plot(xc±y, yc±x)
  if d < 0: d += 2*x + 3
  else: d += 2*(x - y) + 5; y -= 1
  x += 1

✨ Every point stays within 1 pixel of radius r.

3. Scan-line Polygon Fill

Fills polygons with horizontal spans [(y, x_start, x_end), ...] using Edge Tables.

For each scanline y:
  Find edge intersections
  Sort x intersections
  Pair them (x0, x1), (x2, x3)
  Emit span (y, x_left, x_right)

✨ Renders solid bricks & arcade cabinets!

QUEST 4 • CINNABAR ISLAND

The 2D Engine & Inverse Matrix Mouse Picking (`render2d.py`)

+1000 XP

📐 1. Letterbox (Keep 4:3 Aspect Ratio)

When the user resizes the window, the game world (-10 to 10, -7.5 to 7.5) should never stretch or distort! We calculate the letterbox viewport: 

aspect = 4.0 / 3.0
win_aspect = width / height
if win_aspect > aspect:
    vp_w = int(height * aspect)
    glViewport((width - vp_w) // 2, 0, vp_w, height)
else:
    vp_h = int(width / aspect)
    glViewport(0, (height - vp_h) // 2, width, vp_h)

🎯 2. Click-to-Select (Mouse Picking)

How do we know which object you clicked? We invert the object's transform to bring the mouse click into the object's own model space!

  1. Convert mouse pixel (px, py) to world coords (wx, wy).
  2. For each node: inv_M = matrices.inverse2(node.world()).
  3. Transform world click into model coords: (mx, my) = apply2(inv_M, [(wx, wy)])[0].
  4. Point-in-polygon raycasting test against node.figure!

The Professor's Oral Q&A Cheat Sheet

When presenting to the professor or your team reviewer (Member 1), click each question to reveal your exact winning answer:

Q1: "Why does Bresenham's algorithm use only integer arithmetic?" ▼

Answer: Floating-point division and rounding are computationally expensive on early graphics hardware. Bresenham reformulates the line equation into an integer decision variable d = 2Δy - Δx. Because each step only does addition and multiplication by 2 (bit-shift), it runs blazing fast directly in hardware or rasterizers!

Q2: "Why does the Midpoint Circle algorithm only calculate 1/8th of the circle?" ▼

Answer: A circle possesses 8-way symmetry. If we calculate the arc from x=0 to x=y (one octant, 45 degrees), every point (x, y) can be mirrored to 7 other points by flipping signs and swapping coordinates: (±x, ±y) and (±y, ±x). This saves 87.5% of the math!

Q3: "How does mouse click-to-select (picking) work without using OpenGL selection buffer?" ▼

Answer: We convert the mouse screen pixel to a 2D world coordinate using the viewport and orthographic projection bounds. Then, for each node in the scene graph, we take the world point and multiply it by inverse2(node.world()). This maps the mouse click back into the object's local model coordinate system, where doing a simple point-in-polygon ray casting check determines if the object was clicked!

Q4: "Why do we avoid glTranslate / glRotate on objects?" ▼

Answer: The course requirement mandates showing that we understand the underlying transformation math. We compute hierarchical transformations in Python using our own 3x3 and 4x4 matrix multiplication functions in matrices.py, passing the finalized composite matrix to OpenGL using glMultMatrixf(to_gl(matrix)).
